# Witness availability and future enrollment: amended boundaries

Current policy amendment (2026-10-05): **Path B supersedes execution-locality hard stop E and accepts forwarding/remote/VM execution backed by qualifying physical TPM evidence.** The historical K2/A6 locality dependency below is superseded. Hardware authenticity, canonical one-physical-TPM lineage uniqueness, fresh credential activation and physical qualification remain required. See [active amendment](CODEX-PATH-B-ADMISSION-DESIGN-20261005.md); old design/evidence is retained for provenance, not current authority.


Prepared under the user-authorized takeover. This document is a reviewable design, not a new consensus rule, a hardware qualification or permission to seal Genesis. Its source baseline is integration `12c68c1` (including test-only RSA verifier `81f3696`). No production descriptor, roots, PCR values, activation transcript or approved fleet identity-class list was supplied.

## Existing representation and trust boundary

`genesis_v2::Parameters` commits the exact rule manifest, Genesis class, endorsement-root set with per-anchor constraints, PCR-profile set and ordered identity classes. `genesis_v2::verify` compares the decoded inputs with independently supplied `Approved` class, exact manifest bytes and target before reconstructing Genesis. The caller must obtain those expectations independently: copying them from the untrusted artifact is a circular approval. A self-built manifest and Production enum are software fixtures, not physical provenance.

`Provenance::Endorsement` commits ordered `(root, identity)` pairs and `witness_sha256`. `attestation_witness::AttestationWitness` already defines canonical CBOR `[1, reference_time, endorsements, activation]`. Every endorsement carries the exact TPM2B_PUBLIC, leaf-first certificate chain and CRLs. Every activation record names the same class index and AK Name and retains only credential-blob, encrypted-seed and secret commitments. The existing whole-witness bound is 131072 bytes, at most four classes, one activation per class, public area <=1024 bytes, 2..5 certificates <=4096 bytes each and <=4 CRLs <=32768 bytes each. These are proposed software bounds, still to be checked against actual fleet evidence; no larger limit is adopted here.

The existing verifier checks canonical encoding and bounds before expensive verification, commitment equality, exact committed reference time, exact class counts/order, public-area template and key, certificate/CRL profile and root constraints, identity derivation, exact root at each index and AK-name consistency. RSA/ECC keys of different encodings must resolve through the existing canonical identity implementation; all current and retired identities participate in duplicate detection. Coverage is enforced by the constructor and state reconstruction; projected voting authority now also checks those rules without requiring a premature StateRoot.

The original design baseline's certificate syntax was test-only. The takeover successor described in `CODEX-A11-PROMOTION-20261004.md` promotes the independently reviewed bounded RSA/ECDSA parser into the unconditional consensus graph and authenticates available Genesis witnesses with it. The existing test-support path reexports that parser. C-Q2 still requires every affected lock/vendor identity and frozen offline/empty-CARGO_HOME native qualification. Focused parser and available-evidence results do not supply physical provenance or close the prior three-major review by themselves.

## Proposed available witness bundle, without inventing a carrier

1. The Genesis release artifact retains the exact public witness bytes for every initial admission. A bundle indexes them by existing witness commitment and exact admitted binding identity; duplicate commitment with different bytes, missing entries and extraneous identity substitutions are refused. Bundle decoding uses definite lengths and byte-identical re-encoding, with the existing per-witness bounds applied before allocation.
2. A trusted Genesis admission entry point first checks `Approved`, then verifies the member's exact profile/statement, the corresponding available witness against the committed roots/classes/PCR rules, and the independently supervised activation/host-binding evidence. It returns an authenticated admission result only after all checks succeed. `construct` alone remains a deterministic software constructor, not the physical qualification boundary. Missing approved inputs or witness is a refusal, not a fallback to a hash-only assertion.
3. Replay retains and rechecks the same exact witness bytes and commitments under the historical committed reference time and root constraints. An unavailable witness is explicitly incomplete replay capability; a pruned node must retrieve authenticated bytes before making an admission-verification claim. Future witness supply cannot rewrite the committed identity or approvals.
4. For future enrollment the exact public witness must travel with the admission and remain in archival block history. The current JOIN encoding has no such carrier, and a witness may exceed the existing operation bound. A new version/carrier and its charged-byte treatment therefore require an explicit specification; no new kind, fee, wrapping surcharge or unbounded side channel is selected here. Transport fragmentation is byte carriage, not admission authority or consensus availability by itself.
5. Never retain private keys, activation secrets, unlock material or platform credentials. Public EK certificates/keys are correlatable per-chip identifiers; hashing them does not create anonymity. The local custody ceremony stays outside this task.

This is an explicit launch dependency, not the completed decentralized path.

A genuine EK chain and a successful AK/EK activation establish cryptographic identity/possession boundaries; they do not prove where node software executes, that the machine is outside a hosting provider, or that future quotes are not relayed. A transcript from a colluding verifier is forgeable as an account of physical decryption because that verifier already knows the secret. No software test can erase those limits.

The existing design's candidate element is multi-challenger credential activation anchored to a finalized parent: challengers with more than one third of eligible weight independently commit protected challenges, the joiner answers within a specified canonical window, and challengers later reveal MakeCredential seeds for deterministic replay. Under the existing BFT assumption, that threshold would ensure an honest challenger; it is still an unadopted admission rule. Required exact inputs remain the window unit/value, weighted challenger selection and anti-grinding rules, challenge/response/reveal carriers and fee treatment, deterministic MakeCredential algorithms, failure/withholding disposition, canonical epoch/height transition, witness retention and new-member eligibility point. None exists in the current JOIN carrier, and this document does not guess them.

The alternative described by the local design is a manufacturer/OEM-certified IAK/IDevID and fresh certified-AK quote. That requires actual platform certificates, independently approved roots and a precise certificate profile; no such inputs were supplied. It still cannot establish absence of relay or cloud execution.

The direct K2 decision retains hard stop E. Neither candidate element above supplies an enforceable binding between execution and the physical host; neither is adopted as a substitute. Permanent Architect approval, discretionary committee approval and witness assertions are expressly excluded. Unsupported Production admission remains disabled; this is a launch dependency, not completed decentralized enrollment. The software lanes continue.

## Exact available-evidence artifact and replay context

The implementation target is an external Genesis evidence artifact, not a new consensus operation or fee. Its canonical definite-length CBOR is `[1, genesis_id, protocol_fingerprint, [[node_id, witness_bytes]...]]`, with exactly the initial admitted NodeIDs, strictly increasing and unique. Current V2 Genesis has one `member_binding`; its twelve Bootstrap Licenses are not twelve separate nodes. Hash fields are exactly 32 bytes; each witness is at most 131072 bytes; the artifact bound allows at most twelve entries and `12 * 131072 + 4096` bytes, while verification requires exactly the actually admitted node set (currently one). Refuse trailing bytes, indefinite lengths, nonminimal integers, byte-different re-encoding, duplicate/missing/extra nodes, a substituted network identity and oversized input before allocation. The artifact introduces no new key, trust root, enrollment approval or claimed anonymity.

Authentication comes from independently approved Genesis inputs and the verified enrollment: each node's exact admitted statement supplies its existing witness commitment. Verify the witness bytes against that commitment and the exact identity-class list and per-anchor constraints committed by the approved manifest. An unauthenticated bundle index is never the source of a root, class, admission statement or reference time. The bundle names the exact verified GenesisID and protocol fingerprint and cannot be reused under another network.

Genesis certificate validity, CRL signatures/revocation/freshness and witness reference time use `Inputs.timestamp` from the independently approved Genesis artifact. The future post-sealing design uses the canonical finalized parent timestamp named by that admission. A witness's own timestamp is only compared with that context. Replaying historical evidence does not consult the verifier's current clock, OS trust store or a network endpoint, including AIA, OCSP and CRL distribution points. Missing or stale evidence relative to the historical context is a precise refusal.

Retain the exact public artifact and witnesses with every independently retained Genesis release/evidence archive for the lifetime of replay support. Retain future admitted witnesses in their authenticated historical admission evidence once a carrier is specified. A pruned verifier must recover the committed bytes before claiming complete admission validation. Commitment-only state and a successful local download are insufficient. Logs report node/commitment, counts and precise validation failures; they do not routinely print full EK certificates, areas, serials or activation records. Public EK material identifies hardware and must be distributed only as required for independent verification.

The public witness verifier proves certificate/key/identity/commitment and historical-context consistency. It does not prove credential activation from a signed result record. The executable admission entry point must refuse Production with hard stop E until the separately specified enforceable host association exists, even when all public witness checks pass. Software TEST-VALUE construction and replay remain available; neither can enable Production eligibility.

## Concrete host-binding design and exact architectural conflict

Threat model: a malicious node owner may control the host OS and network, relay challenges to an authentic remote TPM, collude with a reporting witness, move the workload after enrollment, or expose a TPM through a virtualized/provider host. A valid EK certificate, AK certification, credential activation and fresh nonce quote can all be relayed. Matching their identifiers establishes which TPM answered; it does not establish where the consensus process ran. A witness knowing an activation secret can forge a result account without demonstrating a TPM's decryption.

A local mechanism would need an independently authenticated hardware endpoint and a measured launch that binds the actual consensus executable, its session keys and the TPM to an enforced local communication path; freshness must bind a challenge to that execution instance and its canonical admission context. Verification would need authentic platform/measured-launch evidence, the exact accepted measurements, an attested channel whose keys cannot be exported by a malicious OS, enforceable isolation from a proxy, and a defined continuity/requalification rule after host or executable change. None of these may be replaced by an operator's assertion. They are requirements for a candidate mechanism, not guarantees furnished by the current TPM command interfaces.

An authorized supervised physical inspection can observe association at enrollment time within its documented trust assumptions. It cannot supply a consensus-enforceable guarantee of future execution locality under this threat model, and K2 forbids making discretionary approval the permanent gate. The precise conflict is therefore: the locked requirement demands enforceable physical-host association, but the current EK/AK/quote/activation protocol and JOIN carrier do not carry independently verifiable execution-locality evidence or exclude remote relay. No supported production eligibility path satisfies that requirement today.

The current implementation enforces the only justified result: hard stop E, with no permissive fallback. Completing decentralized post-sealing enrollment requires an explicit policy decision on a concrete mechanism and its remaining limitations, plus its exact evidence/carrier/eligibility rules. It remains a launch dependency. This document does not silently weaken locality, adopt a new threshold, or call disabled enrollment complete.

- Every production admission and accepted/prospective voting boundary covered; malformed material retains its own refusal before the current A8 scope refusal. No fixture constructor or public mutation API bypasses source guards.
- Independent final-source review, vendor/source provenance and native offline qualification on the frozen integrated bytes. All prior failed, partial and historical evidence remains separately identified.
