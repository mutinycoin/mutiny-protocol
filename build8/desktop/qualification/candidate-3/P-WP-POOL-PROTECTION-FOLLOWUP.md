# WP-POOL strict protection API: source-only tranche

Status at this commit: source reviewed/formatted only; **no Cargo compile/runtime PASS is claimed**. Windows host lease is reserved for other workers. This tranche excludes the unfinished authenticated archive lookup and scale checks.

Ordinary API `submission_pool_v1::private_directory(path)` and associated `SubmissionPool::private_directory(path)` return `Result<bool>`: true only if this invocation created/protected one new leaf, false if an existing private leaf passes checks unchanged. Creation is nonrecursive; failure leaves the partial new path intact and refuses. No existing ACL/mode, user state or prior failed evidence is repaired/moved/deleted. Wallet/test callers can provision a new protected pool workspace without consensus fixture features.

Before writable SQLite open, main SubmissionPool parent, existing/created file and any existing SQLite sidecars must pass protection checks. Unsafe existing state refuses unchanged. Unix ancestors must have root/effective-user owners and forbid group/other writes unless a trusted sticky ancestor protects existing child ownership. Windows ancestor owners must be current user/SYSTEM/Administrators/TrustedInstaller; applicable other allow ACEs cannot grant non-volume ancestor DELETE, DELETE_CHILD, WRITE_DAC/OWNER, generic write/all. Unsupported grant ACEs refuse; inherit-only ACEs do not apply to that ancestor. The final private directory has protected current-user+SYSTEM DACL; files inherit only that pair. Links/reparse points and multiple hard links refuse.

Read-only Windows ancestry inspection found existing D:/Mutiny and old Temp replaceable by additional principals, so this tranche does not qualify them. Only a NEW protected current-user+SYSTEM fixture workspace was created under suitable C:/Users/admin ancestors. Metadata is retained in `D:/Mutiny/build8-targets/codex-archive-evidence-20261004/PRIVATE-FIXTURE-WORKSPACE.json`. Existing ACLs are unchanged. Future process-scoped fixture TMP/TEMP must use that safe workspace, with protected newly created child directories. Earlier public TEST evidence stays at original paths.

Two source tests cover private directory/file inheritance, hardlink refusal, existing foreign directory refusal, replaceable ancestor refusal before child creation, and unchanged unsafe existing raw pool bytes with no SQLite journal created.
