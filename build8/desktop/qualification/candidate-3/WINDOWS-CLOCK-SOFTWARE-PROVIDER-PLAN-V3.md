## Routine implementation prepared

`node/src/host_clock/windows_elapsed.rs` resolves the two documented precise APIs from the already-loaded KernelBase implementation module, using its full OS-supplied system-directory path. A read-only native probe on Windows26200 found neither precise export in Kernel32 (error127), and both in the existing C:/WINDOWS/System32/KernelBase.dll. The first compiled native test therefore failed rather than falling back. The corrected binding passed the actual native and pure tests in Release; the original failure remains preserved. It reads unbiased time, interrupt time, then unbiased time, converts each 100 ns counter to nanoseconds with checked arithmetic, and pairs the interrupt sample with the unbiased midpoint. Missing exports, reversed unbiased samples and conversion overflow refuse. The capture width is retained exactly; no new tolerance, clamp, wall-time fallback or qualification parameter is introduced. The reader returns counters only, not `Elapsed` or UTC; it cannot create an arbitrary boot identity or issue a clock-qualified permission. No caller-selected path, environment DLL search or dynamic loading is accepted.

Pure tests cover exact conversion, odd midpoint, reversed samples, representable maximum/overflow at every input and preservation of a wide capture window. The native sequential test performed 1000 real paired readings without regression, sleeps/deadline extension or ignored tests. These software checks cannot establish drift, suspend/reboot/VM behavior, or UTC authentication. ## Trusted boot identity contract required before wiring ElapsedSource

Provide an approved supported Windows OS/architecture/VM matrix and a kernel-owned per-boot identifier contract: identical for independent processes in a boot, changed by actual reboot, stable across ordinary process restart/suspend, and inaccessible to ordinary account rewrites. A mutable wall-time estimate, PID, process-random UUID or copied registry/file value is refused. Pin the API information class, exact ABI/version/size, identifier byte interpretation, supported Windows builds, and error/zero/unsupported handling. Reading must be bounded and bracketed so a changed boot around paired counters refuses.

`NtQuerySystemInformation(SystemBootEnvironmentInformation)` is a possible implementation candidate, not an approved contract here. Microsoft's public function documentation warns that the function and structures are internal and may change, recommends runtime resolution, and does not document that GUID structure in its supported returned structures. Local SDK26100 `um/winternl.h` search found no BootEnvironment/BootIdentifier declaration. The missing WDK `shared/ntddk.h` search is a missing file, not proof of global absence. No undocumented numeric information class or layout is promoted by this tranche. [Microsoft query contract and compatibility warning](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntquerysysteminformation).

On receiving the concrete contract, implement a closed native reader with exact-length/error/identity validation; no public override of trusted boot identity in normal production graph. Controlled boot readers belong only in tests. Required native probes: two real independent processes observe the same kernel identity; process restart equality; actual reboot change with public before/after evidence; suspend/hibernate and supported VM migration/reset behavior. Read-only software equality alone does not close those physical probes.
