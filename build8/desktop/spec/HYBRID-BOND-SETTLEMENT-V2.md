# Hybrid bond and equivocation settlement candidate

Status: implementation under qualification. Genesis remains unsealed. This does not activate a production executor or authorize production keys.

Bond ownership is the immutable hybrid wallet AddressID recorded at funding. Each create, unbond or withdrawal intent requires both current owner signatures, resolved through the authenticated parent WalletBook. A later wallet rotation changes signing authority without changing the lot owner or payout AddressID. Node, Continuity, Worker and firmware-release keys cannot authorize these operations.

Candidate 3 amendment (Order of 4 October 2026, decisions P1, P4 and Q4; Lane P design qualification/candidate-3/P-LANE-DESIGN-V1.md sections 2, 5.1 and 11.1 with P-LANE-DESIGN-AMENDMENTS-V1.md; work package WP-B; status PROPOSED-UNFROZEN). A bond command is canonical CBOR [2, kind, body-bytes, Ed448-signature, FN-DSA-signature], at most 4096 bytes. Kind 19 requests unbond and 20 withdraws. The command body is version 3: [3, kind, NetworkID, GenesisID, ProtocolFingerprint, operation-envelope, owner-AddressID, current-owner-descriptor, [lot-ID, next-sequence]]. The operation envelope (spec/OPERATION-ENVELOPE-AND-CONFIRMATION-V1.md) replaces the exact height and parent anchor of the retired version-2 body: the command is valid at any inclusion height H inside its signed window [first, last] whose finalized reference is canonical, and its precondition list must be empty because the lot sequence is the command's committed precondition (an envelope precondition is refused, never carried unchecked). The command identity hashes the canonical body under MUTINY-BUILD8-BOND-COMMAND-ID-V3. Each kind signs its canonical body under its own registered hybrid signature domain (BondUnbond, BondWithdraw). Bond creation is the funded BondCreate of operation kind 24 below; kind 18 and its escrow funding are retired and refused by the operation discriminator (test kind_18_and_escrow_pattern_rejected). Canonical body bytes and every signature are mandatory; no legacy fallback is allowed. Code: consensus/src/bond_ops_v2.rs; tests: consensus/tests/bond_ops_v2.rs and consensus/tests/funded_bond_create_v1.rs.

The funded BondCreate (block operation kind 24, Order P1) is ONE canonical operation [2, 24, unsigned-bytes, create-signature, funding-signature], at most 16,384 bytes (the existing per-operation bound), each signature [Ed448-bytes(114), FN-DSA-bytes(1280)]. The unsigned body is [2, 24, NetworkID, GenesisID, ProtocolFingerprint, operation-envelope, owner-AddressID, current-owner-descriptor, [NodeID, HardwareGeneration, nonce], principal, fee, [[transaction-ID, output-index] ...], null | [change-destination, change-atoms]] with 1 to 128 strictly ascending inputs, a principal of at least 100 MUT, and, when change is present, a nonzero destination and positive atoms (absence is null; a zero address is never an implicit burn). The owner key signs one commitment, SHA-256 of the unsigned bytes under MUTINY-BUILD8-FUNDED-BOND-CREATE-COMMITMENT-V1, twice: the lot authorization [MUTINY-BUILD8-FUNDED-BOND-CREATE-AUTHORIZE-V1, commitment] under the BondCreate domain and the funding [MUTINY-BUILD8-FUNDED-BOND-CREATE-FUNDING-V1, commitment, 0] under the wallet Transaction domain. The operation identity hashes the unsigned bytes under MUTINY-BUILD8-FUNDED-BOND-CREATE-ID-V1. A partial exchange object uses the same encoding with null in an absent signature slot; it is never a block item. Validity at inclusion height H = parent height + 1, in this order (consensus/src/bond_create_v3.rs): context; the envelope window and finalized reference, and any optional precondition compared exactly in the bond-create phase; owner authority from the parent WalletBook; both signatures; node and lineage eligibility, unchanged from the retired kind 18; every input present in the running state, created strictly before H, coinbase-mature and owned by an address of the owner's wallet lineage (any generation); change only to the owner's lineage; exact conservation inputs = principal + change + fee; and a fee of at least the length of the complete signed operation (1 atom per byte, the existing transaction rule; no surcharge and no new recipient). Effects, all or none: the inputs are removed, the lot is created with atoms = principal and created height = H, the change coin is created at OutPoint(operation identity, 0) at height H, and reputation lots are recomputed. Each refusal is an exact bond_create_v3::BondError variant (tests in consensus/tests/funded_bond_create_v1.rs, among them altered_or_stripped_funding_rejects_byte_identical, same_block_spend_of_an_input_rejects_whole_block, third_party_input_or_change_rejected, declared_fee_mismatch_rejects_before_install, replayed_create_and_duplicate_lot_rejected and inputs_must_exist_strictly_before_the_inclusion_height; every rejected block leaves the parent records byte-identical).

The lot ID hashes [2, NetworkID, GenesisID, NodeID, owner-AddressID, nonce] under the V2 bond-ID domain (unchanged by candidate 3). No escrow address exists any more: the V2 escrow domain MUTINY-BUILD8-BOND-ESCROW-V2 is retired, and a coin paid to such a hash funds nothing. Withdrawal payout identity hashes its canonical version-3 unsigned body under MUTINY-BUILD8-BOND-PAYOUT-V3, which replaces the retired V2 payout domain, independent of randomized signature representation.

Authenticated bond records use [2, 52, lot-ID, NodeID, lineage, owner-AddressID, atoms, created-height, sequence, unbond-height-or-null, settlement-height-or-null, status, evidence-ID]. The existing minimum, initial lock, checked arithmetic, exposure intervals and 64 locked lots per lineage are preserved. Shared economic code keeps legacy and hybrid boundary behavior identical; legacy encodings still validate legacy Ed25519 keys and do not decode as V2 records.

An unbond committed at U removes Q contribution from the resulting state, effective for voting at U+1. Withdrawal is permitted only when both certified-block conditions hold: height at least B+259,200 and at least U+43,200, where B is the ACTUAL canonical inclusion height of the lot's BondCreate and U the ACTUAL canonical inclusion height of the Unbond, never a signed, window or reference height, and never converted into MiningEpochs or wall time (tests create_signed_early_included_later_starts_age_at_inclusion and unbond_signed_early_notice_at_inclusion). A deposit committed at C first qualifies at C+1. An offense at U remains covered through the inclusive U+43,200 evidence boundary. Lots created only after the offense, or already nonqualifying at that offense, are not retroactively exposed.

Hybrid penalty records use reserved tag 53. They retain both complete votes, canonical order-independent evidence identity, exact inclusion-parent anchor, historical E-1 anchor and roots, and the historical qualifying signer's lineage, hardware/key generations, TPM public identity/profile, dual public descriptor and positive weight. The signer flags are fixed to admitted/physical/eligible/not-revoked by this record's semantics. Import rechecks historical signatures and context, while the independently authenticated checkpoint supplies registry trust. Record contents cannot independently establish physical admission.

The penalty book permanently distinguishes offending-generation tombstones from current-lineage revocation. Reconstruction rejects malformed records and wrong record keys; typed tags cannot hide in opaque protocol records. Future-dated penalty and bond records cannot authorize a parent transition. Mixed legacy/V2 books are rejected.

The command settlement component preflights each owner command against the parent lot even when evidence burns it in this block. It processes all validated evidence first, then permits only surviving withdrawals. Duplicate commands/evidence and wrong inclusion anchors fail without mutating input components. Numeric D is outside this component and is never incremented. Each settled command has an execution outcome (candidate 3, amendment AM-5): 1 Applied (the notice is recorded or the withdrawal is paid) or 2 NoEffectBurned (valid against the parent lot, but same-block evidence burned the lot first, so the command has no effect and no payout coin exists). The outcome is exposed per command identity (bond_ops_v2::CommandSettlement.outcomes, continuity_lifecycle_v2::Transition.command_outcomes, execution::Execution.bond_command_outcomes) for the operation index (test withdraw_with_same_block_evidence_records_no_effect).

Q4 (Order of 4 October 2026), an explicit and narrow economic decision: FeeRule::None applies to the dedicated BondUnbond and BondWithdraw operations only (kinds 19 and 20). They carry no fee field and no input, and settlement moves no fee; a block that declares a fee for them fails its fee total (test bond_commands_are_fee_free_q4). Q4 does not exempt BondCreate funding (kind 24 pays 1 atom per byte of its complete signed operation), ordinary transfers or trades. Replay and admission protections remain: the per-lot sequence allows one Unbond (sequence 1) and one Withdraw (sequence 2) in a lot's life, at most one command per lot per block, owner authority is current in the parent WalletBook, and the signed window and finalized reference are checked at the actual inclusion height (test command_replay_rejected_by_sequence).

The pure Continuity lifecycle composition now accepts hybrid evidence and bond commands alongside participation, rolling refresh and exit. Parent state authorizes acknowledgements and signatures. Participation closes under the existing period rules, exits are scheduled, evidence revokes current lineage eligibility and clears pending controls/freshness, and surviving bond settlement refreshes Q for future heights. The current certificate still uses the original parent weights. Returned components are not a complete executable State; the licensed candidate executor below composes them with deposits and ordinary transactions/rewards. Remaining lifecycle operations and production activation require further integration. Candidate durable installation is qualified separately in HYBRID-FINALITY-STORAGE-V2.md.

The explicit licensed candidate executor composes these partial components with authenticated hybrid payments, coinbase, Worker assignments and funded BondCreates. The executor adds every BondCreate's DECLARED fee to the block fee total before the payment phase (the coinbase exists before the bond-create phase runs); the bond-create phase, in the position of the retired deposit phase after the lifecycle phase, verifies each declared fee by exact conservation, so a lying fee fails the whole block and the coinbase never contains an unpaid fee (test declared_fee_mismatch_rejects_before_install). A BondCreate consumes only coins that existed before its block: a same-block output is never a funding source, and no escrow output exists. Both parent and resulting registry must identify an eligible physical lineage, and a revoked lineage cannot create a new bond. Scheduling an exit does not invent an earlier eligibility cutoff; its existing boundary still controls eligibility. Current-parent owner authority authorizes BondCreates even when a transaction also rotates a wallet in the same block: the old key's create stays valid in that block and a create by the new key is refused until the rotation is in the parent (test stale_owner_authority_and_same_block_rotation_do_not_authorize). In a first resumed (recovery) block the bond-create phase reads the recovery components (test kind_24_in_a_recovery_block_uses_the_recovery_components).

Candidate execution validates all inputs on tentative copies, processes evidence before surviving withdrawals, adds payouts without overwriting existing UTXOs, and recomputes the complete post-StateRoot. No current work-signature identity enters state, preserving the acyclic work commitment. An explicit history-aware entry point is required for evidence; the default entry point supplies no historical authority and rejects it. Parent-bound Join V2 is composed separately after this settlement; rotation/recovery operations still reject. Legacy and transfer-only entry points cannot carry hybrid lifecycle state. Candidate durable finality installation is qualified separately; production activation remains gated.

Candidate assembly needs no funding pre-selection (candidate 3): a funded BondCreate carries its own inputs, and the assembler adds the declared fees of the requested BondCreates to the block fee before its first complete execution. Invalid signatures, capacity violations or failed complete execution reject the requested operation set; operations are never silently dropped. Optional selection of pending payments remains bounded local policy: a pending payment that spends an input of a requested BondCreate fails its trial execution and is skipped (test funded_bond_is_assembled_atomically_from_public_vector in consensus/tests/assembler_v2.rs). The history-aware assembler passes authenticated historical authorities through every trial execution; the default supplies none and rejects historical evidence. The funded public vector reproduces the complete expected body and post-state without changing the parent or pending queue.
