## Exact bytes and distinct recovery purposes

The block body itself is NOT a StateTree record and is NOT an owner-authorized hardware replacement record. Current canonical storage already persists the complete certified BlockEnvelopeV2 bytes in `evidence_v2.envelope`, atomically with finalized/canonical state and undo/index records. `finality_v2::record_with_recovery` performs actual proposal execution, PoW and parent-set certification before inserting that full envelope; `canonical_store_v2::verify_replay_inner` retrieves each full envelope and reproduces its certificate and state transition from trusted Genesis on reopen.

The successor will continue this representation, retaining the exact complete envelope accepted at H, including the complete canonical body, WorkHeader, WorkAuthority and H certificate. Bound: 1,942,044 bytes. Its body is bounded by 262,150, not 262,144. The StateTree `MAX_RECORD=262144`, accepted owner-recovery record SQL bound, signed RecoveryHistoryV2 codec, combined A2 public recovery wrapper bound262144, and transport `RecoveryEvidence` kind7 bound262144 remain unchanged. No oversized body is hidden in any of those records. Dependency and terminal records remain individually below MAX_RECORD under their own exact bounds.

The retained certified envelope uses existing transport kind3 `CertifiedBlock`, whose existing global maximum remains2,097,152. Restart/repair therefore obtains the actual complete bytes through this already defined block route, then authenticates them from the locally trusted canonical finalized parent. A block hash, locator, operation ID or ACK cannot substitute for those bytes. A2 replacement evidence remains a separate kind7 item and cannot be substituted for a block, or vice versa. No new recovery trust authority or timeout is created.

This is complete retained history, not a proposal to split evidence across unauthenticated chunks. No compressed/synthetic reconstructed evidence, external live lookup, network clock or signature reserialization is introduced. Existing transport fragmentation and complete object-hash verification continue unchanged. The first valid representation accepted for a block is retained byte-for-byte; any later valid alternative certificate representation cannot rewrite that retained history.

## State-authenticated capacity selection

A new shared consensus capacity module will preserve the original strict BlockBody API for historical callers and expose a separate bounded candidate structural reader plus an internal rule-selected validation path. Selection is derived from the committed canonical Genesis parameters/rule manifest and fingerprint of the authenticated parent state. The actual canonical-store boundary already derives HeightAuthority from the expected authenticated parent StateRoot; the capacity selector must be derived in that same boundary before candidate execution or new work/custody transitions. Caller booleans, a prefix/version/operation kind, a body marker, a claimed fingerprint or an unverified StateRoot never grants reserve.

Bounded structural decoding of an A2 candidate may consume at most the explicitly approved candidate/body/envelope ceiling, validate canonical encoding/depth/counts and exact supported inner codecs, and return an explicitly untrusted candidate. This is neither pool admission nor BFT/canonical acceptance. Normal historical encode/decode continues to refuse oversized items. Trusted canonical-store replay obtains its selected mode from previously reproduced parent state, not the stored envelope being replayed. Full native admission/withdrawal evidence, context, existing work/signature/quorum rules and hard E remain mandatory after structural decoding.

The capacity rule is committed into the A2 rule description/fingerprint inputs, with exact limits and projection semantics; no local configuration toggles the rule. Public candidates with a missing/wrong rule cannot reach an accepting candidate, proposal, finality or replay transition.

## One reserve and exact projection

Every transaction remains at most16,384 bytes, including FundedRotation transaction tag25. Every ordinary operation remains at most16,384. An oversized operation qualifies only on the explicit A2-selected path and only after complete canonical typed decoding of an admission wrapper version3 kind15/16 (total147,488 maximum) or a withdrawal operation kind25 (total196,608 maximum). Unknown/version-mismatched/malformed/cross-type inputs never use reserve. Small A2 items remain in the ordinary budget.

There is at most ONE oversized recognized A2 operation, and total transactions plus operations including it is at most4,096. Remove exactly that qualifying operation from a copy of the body, retaining height, reward owner, fee field, transactions and all remaining operations in their original order. Canonically re-encode the projection and apply ALL ordinary invariants, including its encoded65536 and raw aggregate65536 caps, item16384 caps, total count, duplicate/canonical-depth checks and participation-ACK ordering. The oversized operation participates in duplicate detection across the full original body as well. No other item may spend unused reserve. Re-encoding the full body must equal its actual input bytes and satisfy262150. Two oversized items refuse atomically.

Checked arithmetic: legacy-projection encoded65536 + extra raw196608 + its CBOR byte-string head5 + an operation-array head delta at most1 =262150. Since original count includes the reserve, the array transition remains at most one byte (including23→24 and255→256); the4096→4097 transition is unreachable/refused. Envelope bound1,745,430 +196,614 =1,942,044. Proposal custody bound512 +8192 +262150 +17 =270871. Global transport2,097,152 remains unchanged.

Namespaces are dispatch positions, not shared integers: transaction list tag25 remains FundedRotation; operation list kind25 is withdrawal; operation kind23 remains DividendClaim. Typed transaction decoding must reject withdrawal bytes, and typed withdrawal decoding must reject FundedRotation bytes. No fee exemption or conversion between transaction and operation namespaces is introduced.

## Store and replay wiring

1. Canonical `commit` derives the selected capacity from the exact parent state/root, validates whole body with the shared implementation, runs original native execution and parent-set certification, and serializes complete envelope under that selected capacity. All monetary/state/index/evidence/undo writes remain one IMMEDIATE transaction and unchanged-parent checks remain mandatory. A refused second reserve or malformed evidence cannot persist partial evidence, a fee change, state root, pool-consumption or reward.
2. `EvidenceStore` candidate reads gain a separately named bounded untrusted read path up to1,942,044. This path does not change the trust of stored rows. Canonical replay must use that path and then authenticate each envelope against the independently reproduced H-1 state and expected parent root. Historical strict read/encode behavior remains available; no structural-only decode becomes a finalized result.
3. Canonical export exposes the actual retained complete encoded bytes under a stable read transaction, with row type/length, height, block hash, committed canonical anchor and selected parent binding checked. Export never creates missing evidence or silently reserializes the certificate. Read-only missing/truncated/oversized/substituted bytes refuse. The receiver independently verifies complete kind3 object identity and native canonical installation; delivery never grants finality.
4. Reopen replays every retained full envelope from trusted Genesis before exporting or accepting canonical work. Parent root, body root, whole canonical byte equality, original WorkAuthority/PoW/certificate and resulting StateRoot/index/undo facts are all rechecked. If a large body/envelope is unavailable or corrupted, reopen fails closed and retains the original database/evidence. This is ordinary replay, not owner hardware recovery.
5. Existing `evidence_v2` schema already stores envelope as a BLOB with no262144 limit. Its schema text and historical store layouts need no blanket widening for this representation. All SQL reads use explicit bounded type/length checks before allocating. State/undo and accepted recovery tables retain their original262144 checks. Any distinct typed A2 ingress or proposal-journal schema is separately registered/versioned/create-new and independently reviewed; no automatic historical migration.
6. Proposal custody needs its approved270871 representation and rule-aware body root/reopen verification. Root coordinates node candidate/work/observation custody ports and typed ingress/relay queues; shared consensus validation must be used at every such path. Existing SignedOperation9 and submission/control queue budgets remain unchanged. A separate bounded typed A2 route and backpressure are required before complete end-to-end closure.
