# Native read-only NTS observer V1

This isolated Cargo workspace's recorded integer1 successor compiled and passed thirteen exact controls, with zero failures or ignored tests. The live-adapter2 successor shares the native timestamp sandwich between live observation and the offline cryptographic control, adds one bounds/refusal control and records exact arithmetic inputs. It compiled as an ordinary standalone diagnostic binary and passed fourteen exact offline controls, with zero failures or ignored tests. Its twelve frozen source files and full evidence set were independently verified in ROOT-NTS-LIVE-ADAPTER2-INDEPENDENT-CLOSURE1.json. This README records the result after that campaign; executable source/lock bytes are unchanged. No live network run or Windows voting qualification is claimed. It installs no service, adjusts no OS clock, reads no custody material and cannot start the voting clock.

The pinned upstream `ntp-proto` commit is 46ec9bb4d5b6cb24f814f5543d85b9138afb4cba (ntpd-rs v1.9.0). Its internal API is explicitly unstable; the exact source, license, dependency lock, portable/native behavior and shipping exclusion need review. TLS 1.3/hostname/certificate verification and NTS packet authentication use upstream code; the OS trust store is an explicit local trust assumption. No `__internal-test` or key-export feature is enabled. Private cookies and exported TLS/NTS keys remain inside the transport library, never output. Public provider profiles are deployment inputs, not consensus constants. NTS-negotiated UDP destinations are honored.

Configuration contains 3–8 provider records: `hostname`, declared `operator`, `key_establishment_port`, and optional `no_smear_profile_evidence_sha256`; `timeout_seconds` is a bounded local diagnostic I/O timeout (1–60), not a nonce/consensus freshness rule. A missing leap profile is preserved as null for diagnostic observation only. A digest reference is not evidence validation. The receipt explicitly records that independent operator and leap-profile validation is pending. Missing actual approved profile evidence must not be replaced with test constants and called qualified.

`diagnostic_bounds` is mandatory, with explicit era lower/upper POSIX nanoseconds, a nonzero public era-context SHA-256 reference, maximum native sampling span, wall-timestamp uncertainty, elapsed drift ppb, maximum RTT and maximum interval uncertainty. No defaults or local-wall era selection exist. Sampling span and wall uncertainty are bounded at one second, RTT at sixty seconds, and initial interval uncertainty at 250 ms. These are inspection limits; the supplied error assumptions and era reference are not independently authenticated measured profiles. The full supplied inputs and that limitation appear in the receipt. Development values never enable a clock factory. The current live route refuses an authenticated response whose checked integer interval fails; floating diagnostic quantities are supplementary.

Public arithmetic inputs include exact send/receive and authenticated remote/local midpoint NTP 32.32 bits, signed delay/root-delay/root-dispersion bits, precision, both native counter pairs, boot identifiers and full pairing/timestamp uncertainty. The pinned upstream timestamp serialization retains the exact integer bits. Duration serialization deliberately does not use its floating-point serde conversion: wrapping a duration onto the zero timestamp exposes its signed two's-complement bits exactly. A control reconstructs the conversion from the emitted public inputs and checks the identical interval. These inputs allow arithmetic reproduction, not third-party proof of the private NTS transport authentication or profile authority. Complete public receipts are bounded at 128 KiB.

Current authenticated responses are required; key establishment alone does not qualify. Actual response corruption and exact replay are exercised separately before/after the accepted response. The offline controls use in-memory TLS/NTS client and server exchanges with fresh ephemeral TEST keys, wrong hostname and trust-root refusals, a genuine NTS reply with authentication extensions removed or damaged, exact replay, and exact encrypted I/O budgets. They open no host networking, store no private key and install no trust root. Integer intervals retain full timestamp/counter sandwich uncertainty, network asymmetry, root delay/dispersion, precision, explicit drift and rounding. Wall steps, changed boot context, regression, excessive uncertainty and ambiguous era refuse. These software intervals still lack authenticated measured hardware profiles and protected restart integration.

The Windows boot query uses an explicitly unqualified internal ABI and the exact reviewed x86-64 OS build 10.0.26200. Unsupported builds, statuses and layouts refuse without a replacement identifier or DLL loading. Its observed same-process stability is not cross-process, restart, reboot, hibernate, protected continuity or physical evidence. Native elapsed-source integration, a complete authenticated uncertainty adapter, protected restart continuity, measured physical profiles and HostClock integration remain finite software/qualification items. A successful diagnostic would not close them.

Every live run uses a new bounded receipt; partial failures are retained separately from offline campaigns. Do not supply production credentials or use this binary as a daemon or a signing authority.
