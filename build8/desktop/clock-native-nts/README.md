Native NTS acquisition and engine bridge — source only

This ordinary library reuses the exact pinned ntp-proto authentication, native elapsed sampling and integer interval algorithms from the separately tested observer. It exposes a private, non-deserializable authenticated observation. A configuration label, profile digest, receipt JSON, another caller's boolean, wall time, NTS key establishment alone or a replayed packet cannot construct that result.

The normal acquisition path retains TLS hostname and OS-root verification, negotiated NTS destinations/ports, actual NTS response processing and complete integer uncertainty accounting. It never adds test roots, steers time, installs a service or prints cookies/keys/transcripts. At most eight configured providers poll concurrently under explicit I/O bounds, and one successful response per configured operator contributes to the batch. Operator labels and profile references are deployment inputs; they do not prove independence or leap behavior.

The Node source bridge accepts only these typed observations. It rounds intervals outward to the existing millisecond engine and checks a separate explicit native multi-source profile: at least three independent operators, the existing N >= 2f+1 relation, initial uncertainty at most250ms, fresh uncertainty at most1000ms, and all drift/holdover/error contributions. It preserves Chrony's separate one-aggregate/zero-fault qualification contract. Mixed leap indications refuse a new calibration; individual announcements can only shorten an existing horizon. Consistent usable source indications use the existing POSIX leap policy. A source outage never resets an existing engine anchor's age.
